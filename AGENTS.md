# Notes for coding agents

Whittle is a macOS voice-writing app: SwiftUI + AppKit, Swift 5 mode, macOS 14+, Apple silicon. The project is
generated by xcodegen from `project.yml`; never edit the `.xcodeproj` by hand, and don't commit it.

**Setting Whittle up, or connecting a different model:** follow
[.claude/skills/whittle-setup/SKILL.md](.claude/skills/whittle-setup/SKILL.md).

## Build and test

```bash
xcodegen generate
xcodebuild -project Scriber.xcodeproj -scheme Scriber -configuration Debug -destination 'platform=macOS,arch=arm64' build
xcodebuild -project Scriber.xcodeproj -scheme Scriber -destination 'platform=macOS,arch=arm64' test
scripts/install.sh    # Release build, signed, into /Applications
```

The old name, Scriber, is still used by the project, targets, modules and the bundle identifier
(`com.personal.scriber`). The product and everything a user sees are called Whittle.

## Layout

- `Sources/ScriberCore/`: logic without AppKit, and the only target with tests (`Tests/ScriberTests/`). The document
  model and diffs (`Editor/`), reading speech (`SpokenMechanics`, `CommandParser`, `VoicePhrases`, `SpanPlanner`),
  formatting (`DraftFormat`), Structure and Review models (`Outline`, `Review`), noise filtering, routing.
- `Sources/Scriber/App/`: the session (`WritingSession`, `WritingSession+Modes`), the panel and its views, the draft
  editor (`DraftEditor`, an `NSTextView` on TextKit 1), the theme and pixel icons.
- `Sources/Scriber/Interpreter/`: the editor models. `CodexEditor.json(...)` is the single path for every cloud call;
  `OllamaInterpreter` is the local one.
- `Sources/Scriber/STT/`: whisper.cpp (`whisper-server`, with `whisper-cli` as fallback) and voice capture.
- `Sources/Scriber/Integration/`: Accessibility (text fields, selections, the field button, pasting) and screen reading.
- `Docs/ARCHITECTURE.md`: why things are the way they are. Read the relevant row before changing a subsystem, and
  update it when a decision changes.

## Rules that matter

- **No tools for the model.** Prompts include text read from the user's screen. Every model call is text in, JSON out:
  no shell, no file access, no MCP. Keep it that way for any new backend.
- **The draft is one plain string.** Formatting lives in it as `• `, `1. `, `**bold**` and `*italic*`; the editor draws
  it, `DraftFormat` normalises model output, `ClipboardText` turns it into HTML on Done.
- **Edits are versions.** Everything that changes the draft goes through `DocumentModel` so undo, the change flash and
  the logs see it.
- **No personal data in the repo.** Examples and tests use made-up people (Lena, Tomas, Sam, Haven Founders). The
  writer's own context lives in `~/Library/Application Support/Whittle/`, never in the repo. No API keys or signing
  identities in committed files; `scripts/local.env` is git-ignored for that.
- **Match the surrounding code**: plain names, short doc comments that say why, no new dependencies without a reason.
  User-facing text is plain and specific.
- Run the tests after any change to `ScriberCore`, and add one when you change behaviour there.
